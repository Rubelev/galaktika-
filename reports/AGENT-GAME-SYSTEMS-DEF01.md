## DEF-261109-01 (P1): `progress.owned` содержал epoch-время

### Причина

В `lib/trophy_core.php → trophy_progress()` карта «сколько у игрока» заполнялась **самим временем получения**:

```php
// было
$owned[$it['id']] = isset($state['items'][$it['id']]) ? (int)$state['items'][$it['id']] : 0;
```

`state['items'][id]` — это `ts` первого получения, поэтому в ответ уходило `"race_helmet": 1794172254`. Одним и тем же значением пользовались и счётчики, проверяя его «на истинность» (`if ($owned[...])`, `foreach ($owned as $ts) if ($ts)`), поэтому `have` случайно совпадал — но контракт API был сломан: UI, ожидающий 0/1, получил бы время, а любая арифметика по `owned` (сумма, прогресс-бар) считала бы миллиарды.

### Фикс

| Что | Стало |
|---|---|
| `progress.owned[item_id]` | **0 или 1** (количество), больше никогда не время |
| `progress.first_at[item_id]` | **новое поле**: epoch первого получения (0, если предмета нет) |
| `have` | число уникальных предметов, считается по наличию (`isset(state['items'])`), а не по «истинности» времени |
| `collected` | **новое поле** = сумма `by_set[].have` (DEF-02) |
| `sets_complete` / `by_set[].collected` / `by_set[].first_at` | **новые поля**: сколько сетов собрано, флаг сета, время закрытия сета |
| `api.php` (`trophy_roll`, `trophy_craft`) | в ответ добавлен `collected` рядом с `have`/`total` |

Ответ для UI **не сломан**: поля `owned`, `have`, `total`, `by_set` остались на месте и с теми же типами; новые поля аддитивные.

### Было → стало (на данных из карточки)

| Поле | Было (прод) | Стало |
|---|---|---|
| `progress.owned["race_helmet"]` | `1794172254` | **`1`** |
| `progress.first_at["race_helmet"]` | — (поля не было) | **`1794172254`** |
| `progress.owned["race_teeth"]` (не получен) | `0` | `0` |
| `progress.have` | 1 (случайно верно) | 1 (считается по наличию) |

Старые «битые» состояния совместимы: в `state['items']` по-прежнему лежит время, прогресс читает его как признак владения и отдаёт `owned = 1`, `first_at = ts` — миграция данных не нужна.

## DEF-261109-02 (P2): `have` / `collected` / `set_complete`

**Подтверждено:** считались из того же испорченного значения, но по «истинности» — на проде цифры совпадали (`have: 1` при одном предмете), потому что `ts > 0`. Это была мина: любое изменение `owned` (например, обнуление времени или предмет с `ts = 0`) ломало бы сразу и `have`, и `complete`, и бонусные сеты.

**Сделано:**
- `have` и `by_set[].have` считаются по `owned === 1`, а не по truthiness;
- `set_complete` = `have === total` сета (по счётчику, не по времени);
- `collected` = сумма по сетам (равна `have`), `sets_complete` — число закрытых сетов;
- `by_set[].first_at` — время закрытия сета из `state['sets']`.
