### 3.1. Разрыв 1 — завод не списывает `food_*`. Подтверждён

Тик колонии при выпуске завода списывает **только кредиты и воду**:

- `api.php:240` — `if ($foodPlan['produced_kg'] > 0) {`
- `api.php:241` — выпуск уменьшает потребность: `$foodNeed = max(0, $foodNeed - $foodPlan['produced_kg']);`
- `api.php:242` — `$profile['credits'] -= $foodPlan['energy_cost'];`
- `api.php:243-245` — `$profile['resources']['water'] -= $foodPlan['water_needed'];`
- **ни одна позиция `food_*` не уменьшается и не пополняется** — в блоке их нет ни одной.

Население ест только зерно, а не склад еды:

- `api.php:259` — `$grain = ... $profile['resources']['grain'] ...`
- `api.php:261-264` — `$foodGot = min($grain, $foodNeed); ... $profile['resources']['grain'] = $grain - $foodGot;`

Единственное место, где вообще появляется ключ `food_<id>`, — рынок еды (покупка/продажа):

- `api.php:2803` — `$resKey = 'food_' . $q['id'];`
- `api.php:2810` — покупка: `+= $q['qty']`; `api.php:2816` — продажа: `-= $q['qty']`

Азот и метан тоже оплачены деньгами, а не складом:

- `lib/food_core.php:20` — `const FOOD_N_PRICE = 3.0; // кредитов за кг азота`
- `lib/food_core.php:79-84` — комментарий: *«АЗОТ: нужен для белка; считаем деньгами, а не складом — иначе у старых игроков без запаса завод встал бы»*, затем `$energyCost += $nitrogenCost;`
- `lib/food_market_data.php:12-15` — у синтетики объявлен `source_resource` (`methane` / `nitrogen`), он отдаётся в API (`lib/food_market.php:22`), но **ни один код его не потребляет** (grep `source_resource` — только эта выдача).

**Следствие (замкнутый цикл «произвёл → съели → заплатил» разорван):**
1. Купленная на рынке еда (`food_carb_paste`, `food_protein_paste`, деликатесы…) **не съедается никогда** — на потребление идёт только `grain`.
2. Произведённая заводом еда **не попадает на склад** — она существует только как вычет из суточной потребности внутри одного тика.
3. Поэтому `food_trade` — чистая покупка «в никуда»: деньги списываются, склад растёт, расходной статьи нет.

**Почему зелёные тесты этого не ловят:** `food_core_test.php` проверяет только формулу плана (`food_capacity` / `food_plan` — 24 проверки, включая азот), ни одна проверка не касается склада и `api.php`. 24/24 не противоречат разрыву.

### 3.4. Разрыв 4 — `lastSeen`/D1. Разрыв устарел наполовину

`lastSeen` **есть**:

- `api.php:1189` — `$parsed['lastSeen'] = time();` (при логине);
- `api.php:1225` — `'lastSeen' => time(),` (при регистрации);
- `api.php:3727` — чтение: `$seen = isset($p['lastSeen']) ? (int)$p['lastSeen'] : 0;`
- **Живая проверка:** профиль агента содержит `lastSeen` (`1793855546`), ключ присутствует в реальных данных.

Но метрика не та, что нужна:

1. **`lastSeen` = «заходил», а не «играл»** — пишется только в `login`/`register`. Ни один игровой запрос его не обновляет (grep `lastSeen` по `api.php` — ровно 3 вхождения: 1189, 1225, 3727). Онлайн-активность считается отдельно, по `presence.json` с TTL (`lib/presence_core.php:50,55`), и в `users.json` не сохраняется.
2. **D1/D7 нет.** `grep -rn -E "retention|D1|D7"` по `lib/*.php` и `api.php` — **0 совпадений**. `stats` (`api.php:3713-3758`) считает `newToday`, `newWeek`, `activeToday`, `activeWeek`, `idleMonth` — это DAU/WAU и «новички за сутки», а не когортное удержание: нет первичного дня (`firstSeen`/дата регистрации как базы когорты) и нет join «день регистрации → активность на N-й день».

**Итог по разрыву:** формулировку «нет `lastSeen`» надо заменить на «есть `lastSeen`, но только с логина; D1/D7 не считаются».
