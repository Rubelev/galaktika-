### Что именно рисуется

- **Сетка 24 плиток**: 4 сета × 6. Состав и порядок — из ответа сервера (`progress.by_set` — порядок сетов, `progress.items` — предметы с `set`), в клиенте нет своей таблицы предметов.
- **Получено / нет**: `progress.owned[id]` → плитка `owned` (цветная, подпись «в коллекции») либо `empty` (серые иконка/имя/жирность, подпись **«осколки N/M»**, где N = `shards`, M = `craft_cost` из ответа).
- **Прогресс**: шапка `have / total` (например `2 / 24`); под ней «сетов собрано X из 4 · осколки: S · бросков осталось N из L»; в каждом сете «собрано K/6» из `by_set[set].have/total`.
- **Призыв к действию при 0**: отдельный блок «Коллекция пуста. Выберите сет и сделайте первый бросок…» (показывается, когда `progress.have === 0`).
- **Бросок**: своя кнопка у каждого сета — «🎲 Бросок (осталось N)», N из `rolls.left`. Нажатие → `trophy_roll {set}`; результат — карточка предмета (иконка, имя, редкость, описание) или «Пусто» / «Дубликат +1 осколок». При **429** — оранжевая карточка «Лимит бросков исчерпан · следующий через N ч» (`wait_sec` из ответа).
- **Крафт**: на недостающей плитке кнопка «Скрафтить · 5 осколков» появляется только когда `shards >= craft_cost` (числа сервера).
- **Никаких наград/кристаллов**: `bonuses`, `bonus`, `crystals`, кредиты не выводятся — только предметы, осколки и лимит бросков.

### Числа — с сервера (не считаются на клиенте)

| Показатель | Источник |
|---|---|
| плитки, имена, иконки, редкость, описания | `progress.items` |
| получен/нет | `progress.owned[id]` |
| `Y/24` | `progress.have` / `progress.total` |
| `собрано K/6`, метка «сет собран» | `by_set[id].have/total/complete` |
| «сетов собрано X из 4» | `progress.sets_complete/sets_total`, если сервер их отдал (v=1273); если нет (v=1272) — число сетов с `complete:true` из `by_set` (агрегация серверных флагов, не пересчёт игры) |
| осколки | `shards`, стоимость крафта — `craft_cost` |
| остаток бросков | `rolls.left` / `rolls.limit` (в ответе броска — `rolls_left`) |
| ожидание после 429 | `wait_sec` (только форматирование «через N ч») |

Совместимость: на выложенном v=1272 `progress` **не содержит** `collected`, `sets_total`, `sets_complete`, `first_at`, а `owned` у полученного предмета — epoch-время (дефект DEF-261109-01, `race_helmet = 1794172254`). Клиент проверяет `owned` на «истинность» (`!!Number(...)`), поэтому одинаково правильно рисует и v=1272, и v=1273 (`1/0`).

## 5. Кеш модуля — исправлено и проверено (2026-11-09, 00:20–00:27 MSK)

`import()` не имеет версии в URL, поэтому браузер держал `js/encyclopedia.js` (без query) в кеше и после выкладки мог исполнять старую копию. Добавлен кеш-ключ:

```
было   solar.js:3937   import('/js/encyclopedia.js')
стало  solar.js:3938   import('/js/encyclopedia.js?v=2')
```

`App.razor:122` — `solar.js?v=3540` → `v=3541`, иначе сам `solar.js` с новым импортом тоже придёт из кеша. `node --check solar.js` — exit 0.

**Проверка в Chrome+CDP** (свежий профиль, локальные `solar.js`/`encyclopedia.js` подставляются вместо серверных через `Fetch.fulfillRequest`, кеш не чистится вручную):

| Что | Значение |
|---|---|
| запросы `Network.requestWillBeSent` | `js/solar.js?v=1273`, затем **`js/encyclopedia.js?v=2`** |
| ответ на модуль | `fromDiskCache=False / fromMemoryCache=`, `status=200` |
| `performance.resource` | `/js/encyclopedia.js?v=2` → `transferSize = 30 842` (из сети, не из кеша) |
| DOM после открытия | активная вкладка «**Коллекция**», `24` плитки, шапка `2 / 24` |

Для контраста в том же профиле без `?v=`: запрос шёл на `/js/encyclopedia.js`, а `transferSize = 0` и `fromMemoryCache` — то есть исполнялась кешированная копия. С `?v=2` URL другой → кеш-хита нет, грузится новая версия.
