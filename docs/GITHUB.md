## 3. Правила сохранения

### Ветки

| Ветка | Назначение |
|---|---|
| `main` | то, что задеплоено на сервер |
| `feat/<тема>` | новая механика, вливается через PR или fast-forward |
| `fix/<тема>` | правка бага |

Правило: **в `main` попадает только то, что проверено на живом сервере**.

### Коммиты

Формат: `<область>: <что сделано>`

```
food: азот в расчёте завода (0,12 кг/кг)
casino: спорт и слоты, RTP 96,76 %
store: профили в SQLite, регистрация снова сохраняет
fix(api): save_json терял users.json после рефакторинга
docs: правила GitHub и .gitignore
```

Один коммит — одна причина. Не смешивать «фикс» и «новую фичу».

### Теги = версия деплоя

Деплой идёт с `-Version NNNN`. После успешного деплоя:

```
git tag v1268
git push origin main --tags
```

Тогда по тегу всегда видно, какой код на сервере.

### Ритуал работы

| Когда | Команда |
|---|---|
| Перед началом | `git pull --rebase` |
| После проверки на сервере | `git add -A` → `git commit -m "..."` |
| Деплой прошёл | `git tag vNNNN` → `git push origin main --tags` |
| Перед деплоем | `git status` — в коммите не должно быть токенов |

## 4. Как проверить, что на GitHub самое свежее

```bash
git fetch origin
git status -sb                 # впереди/позади origin/main
git log origin/main..HEAD      # что есть локально, но не на GitHub
git log HEAD..origin/main      # что есть на GitHub, но не локально
git diff origin/main --stat    # расхождения
```

Признак «всё свежее»: `git status -sb` показывает `## main...origin/main` без `[ahead N]`.

## 5. Что нужно, чтобы это заработало

1. **Логин/организация GitHub** — куда создавать репозиторий.
2. **Приватный или публичный** — вы выбрали «решу позже».
3. **Установка git**: winget нет, поэтому вариант — портативный Git for Windows (zip, без установки) либо установщик вручную.
4. **Доступ на push**: Personal Access Token или SSH-ключ (не хранить в репозитории).
