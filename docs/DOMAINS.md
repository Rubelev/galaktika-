## Зеркало warbattleuniverse.store

**Решение от 29.10.2026: оставляем как рабочее зеркало, не трогаем.**

| Параметр | Значение |
|---|---|
| Статус | зеркало, полная копия `.com` |
| Синхронизация | `rsync -a --delete --exclude uploads/ --exclude .htaccess` |
| Отличие | **самоподписанный сертификат** → браузер показывает предупреждение |
| Причина | в панели reg.ru бесплатный Let's Encrypt для второго домена недоступен |

Предупреждение браузера — известное ограничение. Игроку нужно один раз нажать
«Перейти на сайт (небезопасно)». Данных на домене нет, аккаунты живут в `.com`.

### Почему нельзя выпустить сертификат самим

nginx отдаёт **404** на любой путь, начинающийся с точки:

```
/dotfile.txt                          → 200
/well-known/acme-challenge/t.txt      → 200
/.well-known/acme-challenge/t.txt     → 404   ← ACME HTTP-01 невозможен
```

`certbot` и `acme.sh` на хостинге не установлены, установка сертификата в nginx
требует root. Поэтому сертификат для `.store` может появиться только через панель.

### Как синхронизировать зеркало после правок

**Автоматически:** выкладка идёт через `deploy-host/deploy.ps1` — он сам собирает
статику, заливает файлы на `.com`, синхронизирует зеркало и запускает аудит.

```powershell
cd galaktika\deploy-host
.\deploy.ps1                 # сборка + выкладка + зеркало + аудит
.\deploy.ps1 -SkipBuild      # только выложить текущее
.\deploy.ps1 -Version 705    # с явной версией ассетов
```

**Только зеркало** (когда .com уже обновлён):

```powershell
.\sync-mirror.ps1            # синхронизировать и сверить контрольные суммы
.\sync-mirror.ps1 -DryRun    # показать, что изменится
```

Скрипт сверяет `md5` файлов `index.html`, `app.css`, `js/solar.js`, `api.php`
на обоих доменах и падает с ошибкой, если они разошлись.

**Вручную на сервере:**

```bash
cd /var/www/u3699164/data/www
rsync -a --delete --exclude "uploads/" --exclude ".htaccess" \
      warbattleuniverse.com/ warbattleuniverse.store/
```

`uploads/` не синхронизируется: у доменов свои папки с отзывами.

### Резервный вариант: увести зеркало на .com

Если предупреждение начнёт мешать, в `.store/.htaccess` есть готовое правило —
оно уже лежало в файле `.htaccess.with-redirect`:

```apache
RewriteCond %{HTTP_HOST} ^(www\.)?warbattleuniverse\.store$ [NC]
RewriteRule ^ https://warbattleuniverse.com%{REQUEST_URI} [L,R=301]
```

Скопировать его в `.htaccess` — весь трафик уйдёт на канонический домен
(но https-предупреждение останется, т.к. TLS-рукопожатие идёт раньше редиректа).
