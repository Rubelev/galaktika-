# Бот-инженер и журнал ботов в SQLite

## 1. Что сделано

| Часть | Где | Что делает |
|---|---|---|
| **Журнал ботов** | таблица `bot_log` в `galaktika.sqlite` | каждый бот пишет: кто, что, когда, с какой важностью |
| **База проблем** | таблица `bot_issue` | агрегирует повторяющиеся проблемы: код, важность, счётчик |
| **Бот-инженер** | `lib/engineer_core.php` | проверяет движок, собирает проблемы, готовит отчёт |
| **Суточный статус** | cron `5 9 * * *` | раз в сутки пишет `engineer-report-ДАТА.txt` и строку в журнал |
| **API** | `engineer_status`, `engineer_scan`, `bot_log` | только для админа |

## 2. Новые таблицы

```sql
bot_log(id, ts, bot, kind, level, action, payload)
   bot  = civ | mob | engineer
   kind = tick | economy | story | scan | daily
   level= info | warning | error | critical

bot_issue(id, bot, code, severity, message, context,
          count, first_ts, last_ts, status)
   UNIQUE(bot, code) — одинаковые проблемы суммируются, а не дублируются
   status = open | fixed
```

Прежние JSON-логи (`civ-log.json`, `mob-log.json`) остались как быстрый архив,
но источник истины для разбора — SQLite.

## 3. Что проверяет инженер

| Код | Важность | Проверка |
|---|---|---|
| `civ.state_missing` | critical | нет состояния цивилизаций |
| `civ.negative_resources` | critical | у цивилизации минус по кредитам/еде |
| `civ.tick_stale` | high | цивилизация не тикала > 30 мин |
| `civ.cap_exceeded` | medium | территория/флот/влияние сверх потолков |
| `mob.catalog_size` | high | мобов не 600 |
| `mob.negative_balance` | critical | у моба отрицательный баланс |
| `mob.over_cap` | medium | моб копит сверх потолка |
| `mob.conservation_broken` | critical | не сходится тождество экономики мобов |
| `mob.log_missing` | high | нет журнала тиков мобов |
| `bots.errors_24h` | high | ошибки ботов за сутки |
| `engine.tick_gap` | high | тик не писал в журнал > 30 мин |

**Закрытие проблем:** если проверка больше не находит проблему, инженер сам
переводит её в `fixed`. Иначе старые ошибки висели бы вечно.
