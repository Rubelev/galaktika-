### 1.1 Главная находка: слой фона уже есть, но на сцене его не видно

`backdrops.js` создаёт фиксированный слой `#gx-backdrop` с `z-index: 0` (`backdrops.js:81`).
А сцена сидит в `.solar-system-container` с `position: fixed`, `width/height 100vw/100vh`,
`background: #000`, `z-index: 9999` (`app.css:170`) и становится видимой после входа
(`solar.js:506`).

Значит:
- **до входа** (экран приветствия) градиент виден — подтверждено скриншотом [bg-audit-solar-normal.png](../reports/bg-audit-solar-normal.png);
- **после входа** сцена закрывает слой своим чёрным фоном.

Это **не проверено в живом сеансе с аккаунтом** (в headless-браузере сцены нет: контейнер
остаётся `visibility:hidden`, поэтому на всех снимках виден только градиент). Вывод сделан по
CSS и коду, а не по живому экрану — при приёмке проверить скриншотом под токеном.

## 4. Продвижение: как фоны работают на маркетинг

Фон — это не украшение, а **фабрика контента**: каждый экран становится готовым кадром.

| Что даёт фон | Как используется |
|---|---|
| Скриншоты для соцсетей и каталогов | 5 настроений = 5 разных кадров, не «ещё один тёмный космос». В каталог идёт по одному кадру с M1/M3/M4/M5 + один крупный план UI (сколько именно просит конкретный каталог — смотреть в его правилах, не выдумывать) |
| OG-картинки страниц | своя OG под каждый экран: главная, `?pv=`, `?vegas=1`, `?world=war`, `?world=race`. Сейчас одна на весь сайт: `deploy-host/site/index.html:20` → `images/og-galaktika.png` (365 903 Б = 357 КБ) |
| Обложки YouTube / Telegram | 16:9 из панорамы + заголовок: «Кеп-Вегас» на бордо, «Арены Вармира» на крови, «Гонки Тарсиса» на льду |
| Узнаваемость | правило: **любой** кадр игры должен опознаваться по 2 признакам — тёмная база + один цветовой акцент настроения. Это дешевле логотипа и работает в 1:1 и 9:16 |
| Devlog | каждый фон — отдельный пост «до/после» с парой скриншотов (в `docs/MARKETING.md` § 3 devlog — канал № 2) |

### Что снимать первым (порядок)

1. **Сцена Солнечной системы** — это первое, что видит игрок и каталог; кадр «Солнце + орбиты + звёзды».
2. **Кеп-Вегас** — самое отличимое: бордо/латунь ни с чем не спутать, лучший «крючок» для соцсетей.
3. **Арены Вармира** — самый «громкий» кадр (кровь/металл), идёт в YouTube-обложку.
4. Дальше: Тарсис (лёд), колония (янтарь), планетарный вид (уже с панорамами неба).

Правило съёмки: 1400×900 (ПК) + 1080×1920 (телефон, вертикаль), без модалок и туториала —
`?shot=1&onb=1` (как в скриншотах этого документа), сохранять в `galaktika/reports/`.

## 5. Технические требования

### 5.1 Читаемость UI: контраст текста ≥ 4.5:1

Посчитано по формуле WCAG (относительная яркость sRGB) для текста на базовом цвете настроения:

| Mood | Текст | Фон | Контраст | Акцент | Контраст |
|---|---|---|---|---|---|
| M1 Глубина | `#dce8f7` | `#03060c` | **16,35 : 1** | `#8ab4f8` | 9,63 : 1 |
| M2 Дымка | `#dce8f7` | `#04070e` | **16,25 : 1** | `#9fd0ff` | 12,42 : 1 |
| M3 Бордо | `#e8eef8` | `#160b12` | **16,52 : 1** | `#e6cf95` | 12,58 : 1 |
| M4 Вармир | `#e8eef8` | `#180a0c` | **16,57 : 1** | `#ff8a8a` | 8,51 : 1 |
| M5 Лёд | `#dce8f7` | `#0a1520` | **14,84 : 1** | `#8ff0ff` | 14,09 : 1 |

Требования к реализации:
- фон **никогда** не светлее среднего: тёмная база обязательна, иначе ломается вся типографика UI;
- **запрещено** светлое настроение с белым текстом: `#ffffff` на `#f2f3f5` = **1,11 : 1** (провал).
  «Олимпийский белый» зоны спорта — это **акцент на тёмном** (`#f2f3f5` как пятно света), а не фон;
- если под текстом градиент — брать **самую светлую** точку градиента и проверять по ней;
- полупрозрачные панели (`rgba(15,25,45,.75)`, `app.css:145`) повышают контраст — оставлять как есть.

### 5.2 Вес: ≤ 200 КБ на фон

| Ассет | Вес | Вывод |
|---|---|---|
| Панорамы неба `images/skies/*.webp` (53 шт.) | 1 800 – 27 008 Б | в норме, с запасом |
| `backdrops.js` (все 8 настроений) | 7 097 Б | в норме |
| `images/og-galaktika.png` | 365 903 Б | **вне бюджета** — но это OG-карточка, не игровой фон; при замене OG держать ≤ 200 КБ |
| Текстуры планет `images/*.jpg` | до 1 127 678 Б (`ceres.jpg`) | **вне бюджета**, но это текстуры 3D, а не задники — на фоны не переиспользовать |

Правило: новый фон = один `.webp` ≤ 200 КБ **или** чистый CSS/canvas (0 КБ).

### 5.3 Без мерцания

- Звёзды на сцене статичные: `drawStars()` вызывается один раз (`solar.js:8950`), мерцания нет — не добавлять.
- Не анимировать прозрачность/яркость полноэкранного слоя: «дыхание» через `transform` дешевле
  (сейчас `backdrops.js:114-121`), но постоянный `requestAnimationFrame` **крутится всегда** —
  останавливать при `document.hidden` (частично сделано) и на слабых устройствах (не сделано).
- Смена настроения — один `transition` 0.5–0.6 с (`backdrops.js:81`, `:85`), без мигания белым.

### 5.4 Отключение на слабых устройствах (сейчас **не реализовано**)

В коде игры **нет** ни одного `navigator.deviceMemory`, `navigator.connection.saveData`,
`navigator.hardwareConcurrency` — единственное упоминание `prefers-reduced-motion` во всём
игровом JS: `backdrops.js:74`. Требования:

1. `prefers-reduced-motion: reduce` → без анимации фона (уже есть), без параллакса.
2. `navigator.connection.saveData === true` → только уровень «а» (градиент), без canvas-звёзд.
3. `navigator.deviceMemory <= 2` ГБ **или** `hardwareConcurrency <= 2` → только уровень «а»,
   «дыхание» выключено.
4. Экономия батареи: при `document.hidden` и при `visibilitychange` — остановка rAF.
5. Ручной тумблер «Фон: полный / простой / выкл» рядом с существующим «Звёзды»
   (`solar.js:4386-4401`) — чтобы игрок сам решал, как в тумблере звёзд.

### 5.5 Мобильные пропорции

- Фон — `position: fixed; inset: 0` без `background-attachment: fixed` (на iOS тормозит).
- Градиент задавать в процентах/`radial-gradient(1200px 800px at …)` — на 360×640 и на
  1920×1080 одна и та же композиция не должна «съезжать» в пустой угол; безопасная зона —
  центр 60 % (там UI), детали — по краям.
- Учитывать `viewport-fit=cover` (`deploy-host/site/index.html:6`) — не рисовать важное в
  зонах «челки», отступ 24 px.
- Телефоны сейчас определяются как `innerWidth <= 760` (`mobile.js:16`) — на этой же границе
  проверять кадр 1080×1920.
