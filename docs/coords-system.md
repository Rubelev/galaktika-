# Единая система координат «Галактики»

Документ фиксирует модель координат и порядок перевода на неё отрисовки.
Проблема, которую он решает: сейчас планеты, корабли и пунктир трасс
считаются в трёх разных системах, поэтому борта «уезжают» и не лежат на линиях.

## 1. Уровни координат

| Уровень | Единицы | Кто задаёт | Что хранит |
|---|---|---|---|
| `WORLD` | пиксели сцены, начало — Солнце (0,0) | `WorldCoords` | положение планет, кораблей, пояса |
| `SCREEN` | пиксели окна, начало — левый верхний угол | браузер | то, что видит игрок |

Правило: **вся игровая логика живёт в `WORLD`**, `SCREEN` получается только
на этапе отрисовки одной функцией преобразования.

## 2. Время — единственный источник движения

```
WORLD(timeMs) -> position
```

Никаких «прогрессов», хранящихся в DOM. Позиция объекта всегда вычисляется
из времени и орбитальных элементов:

```js
WorldCoords.at(timeMs).planet('mars')   // {x, y}
```

Следствия:

- при ускорении времени, паузе и перезагрузке страницы борта остаются
  там, где должны быть;
- два клиента с одинаковым временем видят одинаковую картину;
- «догон планеты» считается честно: цель берётся на момент прибытия.

## 3. Орбитальная модель

Каждая планета описывается элементами:

```js
{ id: 'mars', a: 1.524, e: 0.0934, periodDays: 686.98, epochDeg: 355.45, radiusKm: 3389 }
```

Радиус в пикселях — из таблицы масштаба (`ORBIT_SCALE`), одинаковой для
планет, пояса и кораблей:

```js
[1.000, 185], [1.524, 228], [2.100, 245], [3.300, 300], [5.203, 330]
```

## 4. Одна система позиционирования

Все слои (планеты, корабли, трассы, пояс) кладутся **в один контейнер**
`.solar-system` и позиционируются одинаково:

```js
el.style.transform = `translate(-50%,-50%) translate(${x}px,${y}px) rotate(${ang}deg)`;
```

Запрещено смешивать `left/top` от угла слоя и `left:50%;top:50%` у SVG —
именно это давало рассинхрон.

## 5. Преобразование камеры

Камера — одно аффинное преобразование, применяемое к контейнеру:

```
порядок: translate(posX,posY) rotateZ(spin) rotateX(tilt) scale(s)
```

`WORLD -> SCREEN`:

```js
screen = center + R(spin) * R(tilt) * (world * s) + pan
```

Обратное преобразование нужно только для кликов:

```js
const p = WorldCoords.fromScreen(clientX, clientY);
```

## 6. Проверки (обязательные)

| Проверка | Допуск |
|---|---|
| Начало трассы = планета отправления | ≤ 1 px |
| Конец трассы = планета прибытия | ≤ 1 px |
| Борт лежит на своей трассе | ≤ 2 px |
| Астероид пояса в кольце 245…300 px | 100 % |
| Жилой сектор внутри кольца | 100 % |

Проверки выполняются в `WORLD`, а не в `SCREEN` — экранные координаты
искажены зумом и наклоном.

## 7. Порядок перевода (без «большого взрыва»)

1. Модуль `worldcoords.js` — источник позиций планет (готов).
2. Перевод планет на `WorldCoords.at(...).planet(id)`.
3. Перевод пояса и жилых секторов.
4. Перевод торговцев и флотов на `route(startTime, from, to)`:
   маршрут фиксируется при вылете, точки берутся из `WorldCoords`.
5. Перевод гражданских бортов (орбита вокруг своей планеты).
6. Удаление старых функций `planetPoint`/`updateFleetDots` и всех `left/top`.

После каждого шага — скриншоты по правилам 22/23 и проверки из раздела 6.

## 8. Инварианты

- В `WORLD` нет отрицательных радиусов: всё в пределах `maxOrbitRadius`.
- Любой объект имеет адрес: планета — `id`, астероид — `ПОЯС-SS-NNN`,
  жилой сектор — `Жилой сектор A…L`.
- Время монотонно, шаг не влияет на положение (только на гладкость).
