# Экономия токенов: что сделано и как пользоваться

Правило из общего репозитория (`state\ПРАВИЛО_ЭКОНОМИИ.md`): **сокращаем слова, не проверки.**
Отчёт может быть на 500 строк — он в контекст не попадает. Дорого — когда его пересказывают.

## Что сделано

| Инструмент | Было | Стало | Экономия |
|---|---|---|---|
| Аудит сервера | 61 строка / 2,4 КБ | **2 строки / 0,1 КБ** | **×24** |
| Дневной отчёт | 69 строк / 1,9 КБ | **3 строки / 0,2 КБ** | **×10** |
| Статус игры | 4 запроса вручную | **1 строка** | — |

## Как пользоваться

```powershell
python galaktika\tools\brief.py audit    # аудит: ok + провалы
python galaktika\tools\brief.py report   # сервер, игроки, пожелания
python galaktika\tools\brief.py status   # health + онлайн + тик
python galaktika\tools\brief.py all      # всё по 2 строки
```

Бриф-режим работает так: скрипт выполняется целиком, его вывод ловится в буфер,
в ответ попадают только итог и провалы. Полные данные остаются в файлах
(`reports/2026-*.md`, `reports/audit-*`).

## Правила для меня (и для любого агента)

```
1. ОТВЕТ — до 8–10 строк. Детали — по прямому запросу.
2. НЕ пересказывать отчёт, который уже лежит в файле: числа + ссылка.
3. ЧИТАТЬ — grep/tail/заголовки, а не файл целиком.
4. ОДНА команда — несколько проверок (аудит + отчёт + статус одним вызовом).
5. СКРИНШОТ — только когда без картинки вывод невозможен.
6. НЕ «пробовать ещё раз» после ошибки — сразу другой путь.
7. Числа вместо слов: «47/47», «0,13 мс», «35,2 КБ», а не «всё работает».
```

## Граница качества (не сокращается никогда)

```
1. Приёмка — только с числом.
2. Доказательство — запрос, дамп, скриншот.
3. Сверка «до/после».
4. Бэкап перед правкой.
5. Критерий сформулирован ДО работы.
6. «Не проверено» пишется прямо.
```

## Где что лежит

| Файл | Роль |
|---|---|

| `deploy-host/daily_report.py` | полный дневной отчёт |
| `reports/*.md` | полные отчёты (в контекст не читаются) |
