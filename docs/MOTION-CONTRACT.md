# Контракт механики движения (клиент = сервер)

Документ фиксирует **единые правила движения** для всех кораблей и порядок добавления новых команд.
Любая новая команда должна проходить только через этот контракт — иначе снова появятся «вторые формулы».

## 1. Принцип

```
одна функция времени  +  один набор команд  +  одна таблица скоростей
        │                       │                     │
   poseAt(t)              orders[]              SPEEDS (класс → км/с)
```

- Клиент **не считает** движение сам: он вызывает `poseAt()` и рисует результат.
- Сервер **не хранит** координаты: он хранит `orders[]` и время, а позицию получает тоже из `poseAt()`.
- Позиция — **чистая функция** `(orders, t, world)`. Нет состояния кадра, нет накопленных `progress`.

## 2. Данные

```js
world = {
  bodies: { earth: {x, y, r}, mars: {...}, moon: {...} },   // центры и радиусы
  kmPerPx: 808649
}

ship = {
  id: 'trade-17',
  cls: 'hauler',            // ключ из SPEEDS
  orders: [                 // очередь команд, сервер — источник истины
    { op: 'MOVE_TO', to: 'earth', orbit: true },
    { op: 'LAND',    at: 'moon' },
    { op: 'LOAD',    cargo: 'ice', qty: 120 },
    { op: 'MOVE_TO', to: 'jupiter' },
    { op: 'UNLOAD' }
  ],
  startedAt: 0              // игровые мс, когда очередь запущена
}
```

## 3. Таблица скоростей (единственная)

| Класс | Доля от `BASE_KM_S` = 50 000 км/с |
|---|---|
| fighter | 1.00 |
| light | 0.40 |
| hauler | 0.30 |
| heavy | 0.15 |

Плюс два общих ограничения:

1. **Не быстрее света**: `v ≤ 0.95 c`.
2. **Не быстрее экрана**: `v ≤ 1 px / 45 игровых секунд` (дальние плечи визуально не «проскакивают»).
3. **Минимум 600 игровых секунд на плечо** (10 минут реального времени при 1×).

## 4. Команды

| op | Параметры | Что делает |
|---|---|---|
| `MOVE_TO` | `to`, `orbit?` | перелёт к телу, в конце — виток или подход |
| `ORBIT` | `at`, `radius`, `turns` | круговой облёт |
| `LAND` | `at` | снижение с орбиты на поверхность |
| `LOAD` | `cargo`, `qty` | погрузка (стоянка) |
| `UNLOAD` | — | разгрузка (стоянка) |
| `HOLD` | `sec` | ждать на месте |
| `PATROL` | `points[]`, `loops` | обход точек по кругу |
| `RETURN` | — | вернуться на базу приписки |

### Как добавить новую команду

```js
MotionCore.defineCommand('JUMP', {
    duration: (order, ctx) => 120 * 1000,          // мс игры
    pose: (order, k, ctx) => ({                     // k = 0..1 внутри команды
        x: ctx.from.x + (ctx.to.x - ctx.from.x) * k,
        y: ctx.from.y + (ctx.to.y - ctx.from.y) * k,
        ang: ctx.ang
    })
});
```

Достаточно одной регистрации — команда сразу доступна и клиенту, и серверу, потому что обе стороны вызывают один и тот же `poseAt`.

## 5. Ответственность сторон

| Что | Клиент | Сервер |
|---|---|---|
| Хранение `orders[]` | копия для отрисовки | **источник истины** |
| `poseAt(t)` | каждый кадр | при сохранении/проверке |
| Продвижение по очереди | по времени | по времени, авторитетно |
| Проверка скорости | нет (не считает) | да, при постановке приказа |
| Новые команды | через `defineCommand` | тот же регистратор (порт 1:1) |

## 6. Что запрещено

- Считать позицию внутри `update*Traffic`/`update*Fleet` — только `poseAt`.
- Держать `progress` на объекте маршрута (он «плывёт» при перезагрузке).
- Дублировать таблицу скоростей в `solar.js` или `api.php`.
- Добавлять команду без записи в этот документ и без теста.

## 7. Приёмка

| № | Проверка | Инструмент |
|---|---|---|
| 1 | `poseAt` детерминирована: одинаковый вход → одинаковый выход | `tools/motion_core_test.js` |
| 2 | Скорость ни в одной команде не превышает 0,95 c | там же |
| 3 | Новая команда подключается без правок ядра | там же (пример `HOLD_PATTERN`) |
| 4 | Очередь команд проходится по порядку и заканчивается | там же |
| 5 | Клиент и сервер дают одну и ту же позу на одном входе | сравнение JSON-вывода |
