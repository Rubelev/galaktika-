# Ограничения: ядро, производительность, место

Эти три вещи — не «потом», а рамка для каждого шага плана.
Любой шаг, который выходит за бюджет, не принимается.

---

## 1. Ядро (единый источник истины)

| Правило | Проверка |
|---|---|
| Позиция тела — только `SceneModel`/`OrbitKepler` | поиск по коду: нет вторых формул позиций |
| Скорость — только `ship_class` | все `vmax`/`accel` читаются из каталога |
| Команды — только `motion-core` (`poseAt`) | нет формул длительности перелёта вне ядра |
| Системы — только через `SystemRuntime` | `grep` не находит прямых обращений к телам системы |
| События — только через `Scenario` | нет условий шагов вне движка |

**Бюджет ядра:** один новостной проход на кадр, ноль аллокаций на тело
(позиции пишутся в переиспользуемые объекты).

---

## 2. Производительность

### Бюджет кадра (60 FPS = 16,7 мс)

| Слой | Бюджет | Сейчас |
|---|---|---|
| Позиции всех тел (42) | ≤ 0,5 мс | 0,02 мс (замер ядра) |
| Позиции кораблей (48) | ≤ 0,5 мс | 0,05 мс |
| Рендер DOM-маркеров | ≤ 2 мс | ~13 мс на 2 000 узлов (замер) |
| Canvas-слой кораблей | ≤ 2 мс | ~1 мс на 600 |
| Интерфейс/панели | ≤ 1 мс | не измерено |

### Правила

| Правило | Почему |
|---|---|
| Один `requestAnimationFrame` на сцену | несколько RAF = двойная работа |
| Корабли обновляются 30 Гц, планеты — по изменению | половина работы впустую |
| Никаких `filter: drop-shadow` на десятках узлов | каждый фильтр — перерисовка |
| `backdrop-filter` отключается при наклоне | tilt=45 давал 1,8 FPS |
| Корабли — на canvas при > 300 штук | DOM не держит |

**Проверка:** `?perf2=1` — FPS, худший кадр, длинные задачи, DOM, память.
Приёмка: **≥ 50 FPS на среднем кадре**, худший кадр ≤ 50 мс.

## 3. Место (данные, память, диск, сеть)

### Сеть

| Что | Бюджет | Факт |
|---|---|---|
| Каталог (`catalog.js`) | ≤ 20 КБ (gzip ≤ 5 КБ) | 15,1 КБ / ~3,3 КБ |
| На систему | ≤ 3 КБ | ~1,5 КБ |
| Новые скрипты шага | ≤ 15 КБ (gzip ≤ 5 КБ) | — |
| Ассеты на планету | 0 КБ (процедурно) | ✅ |

### Память клиента

| Что | Бюджет |
|---|---|
| JS heap | ≤ 80 МБ |
| GPU-текстуры | ≤ 32 МБ |
| DOM-узлы | ≤ 2 500 (сейчас 720) |
| Маркеры | ≤ 300 на DOM, дальше canvas |

**Проверка:** в `?perf2=1` смотреть DOM и память; утечка = рост за 30 с.

### Диск хостинга

| Что | Бюджет |
|---|---|
| Сайт (без данных) | ≤ 40 МБ |
| `galaktika-data` (JSON/SQLite) | ≤ 20 МБ |
| Бэкапы | ≤ 3 копии по 10 МБ |
| Скриншоты/отчёты в репозитории | ≤ 5 МБ, старое чистим |

**Проверка:** `du -sh` на сервере перед каждым крупным деплоем.

## 4. Как это встроено в этапы

| Этап | Что бюджет проверяем |
|---|---|
| 1. Единый рендер | каталог ≤ 20 КБ; тела 42 в DOM; отклонение ≤ 6 px |
| 2. Агенты | 48 бортов ≤ 0,5 мс; 5/5 кликов |
| 3. Тарсис | рельеф чанками: GPU ≤ 32 МБ; 40–60 % кадра |
| 4. WW | таймер в профиле, не в памяти вкладки |
| 5. События | 0 лишних DOM на шаге |
| 6. Сервер | SQLite ≤ 20 МБ; ответ API ≤ 200 КБ |

---

## 5. Красные линии

- Шаг, который добавляет **вторую формулу** позиции/скорости — не принимается.
- Шаг, после которого **FPS < 50** на базовом кадре — откат.
- Шаг, который **раздувает каталог** сверх 20 КБ — пересборка данных.
- Шаг, который **не имеет числа приёмки** — не считается сделанным.
