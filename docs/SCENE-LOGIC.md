# Логика сцены: одна модель вместо правок «под кадр»

## Проблема, которую это решает

Раньше каждая часть сцены считалась по своей формуле:

| Что | Откуда бралось |
|---|---|
| линия орбиты | табличная шкала `orbitRadius(au)` |
| положение планеты | `WorldCoords.planetAt(id, t)` |
| кольца Сатурна | наклон «на глаз» в CSS |
| свечение Солнца | `box-shadow` |
| порядок отрисовки | z-index в разметке |

Отсюда — Меркурий в 19 px от своей орбиты, Сатурн в 7 px, квадратное Солнце,
вытянутые кольца. Каждый дефект приходилось править отдельно, и после
следующей правки он возвращался.

## Решение: `SceneModel`

Модуль [scene-model.js](../src/galaktika.Web/wwwroot/js/scene-model.js) — чистая
математика, без DOM. Один вход (данные тела + время + камера) → один выход
(что и где рисовать).

```js
SceneModel.frame(bodies, timeMs, camera)
```

Возвращает по каждому телу:

| Поле | Смысл |
|---|---|
| `orbit.r` | радиус орбиты |
| `pos.x, pos.y` | экранная позиция |
| `pos.depth` | глубина (для порядка отрисовки) |
| `radius` | размер на экране |
| `rings` | параметры колец (наклон от оси планеты) |
| `glow` | свечение (только звезда) |

### Гарантии по построению

| Свойство | Почему невозможно нарушить |
|---|---|
| Планета **на своей орбите** | `orbit.r` и `pos` считает одна функция `orbitPosition` |
| Кольца **в плоскости экватора** | `ringFrame` берёт `axis_tilt_deg` из каталога |
| Свечение **круглое** | `glow` — радиус и цвет, рисуется градиентом |
| Порядок **по глубине** | `frame()` сортирует по проекции `depth` |
| Размеры **в границах** | `pxForRadius` сжимает корнем и ограничивает min/max |

## Тесты: `tools/scene_model_test.js`

```
12 проверок · 12 успешно · 0 провалов
```

Проверяется: орбита = позиция, радиус орбиты не зависит от времени,
кольца привязаны к оси, свечение только у звезды, порядок по глубине,
размеры в границах, на tilt=85 координаты конечны.

## Как это меняет разработку

| Было | Стало |
|---|---|
| новый дефект → правка в рендерере | дефект → правка **модели**, тесты не дают вернуть |
| новая система = копия кода | новая система = **данные** (каталог), модель та же |
| рендерер считает геометрию | рендерер только рисует `frame()` |

## План внедрения

1. ✅ Модель и тесты.
2. ⏳ `solar.js`: позиции планет и линии орбит — из `SceneModel.frame`.
3. ⏳ Рендерер DOM: рисует `frame()` (планеты, орбиты, кольца, свечение).
4. ⏳ Гибрид canvas: тот же `frame()` — второй рендерер, не второй источник истины.
5. ⏳ Каталог (SQL) даёт данные в `frame()` — новая система без правок кода.

Правило на будущее: **если что-то рисуется в двух местах — это дефект архитектуры**,
а не повод синхронизировать формулы вручную.
