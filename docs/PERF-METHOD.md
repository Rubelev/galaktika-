# Методика измерения производительности

## Главное правило

**FPS нельзя мерить с `--virtual-time-budget`.** Этот флаг прокручивает время
виртуально и ломает `requestAnimationFrame`: зонд показывает 0 кадров или мусор.
Именно так появились «2–6 FPS» и «0,0 FPS», которые оказались артефактом.

## Как мерить правильно

Инструмент: `tools/measure_fps.js` (CDP, реальное время).

```
node tools/measure_fps.js "<url>" <секунды> <порт>
```

Что делает:
1. Запускает Edge headless **без** `--virtual-time-budget`, с `--remote-debugging-port`.
2. Ждёт реальные N секунд.
3. Читает `document.title` (зонд `?perf2=1` пишет туда `PERF fps=… worst=… dom=…`).
4. Дополнительно считает кадры своим `requestAnimationFrame` за 3 с.

## Замеры от 2026-11-01 (headless, без GPU, окно 1400×900)

| Режим | FPS зонда | FPS своим счётчиком |
|---|---|---|
| старый вид | 6,1 | 4,3 |
| `?render=catalog` | — | **9,9** |
| старый вид, всё новое выключено (`?off=sync,catalog,boot`) | 5,0 | 5,8 |

Вывод: разница между рендерами **реальна** (каталог ~в 2 раза быстрее), но
абсолютные числа низкие из-за **программного растеризатора headless без GPU**.
Для живого игрока эти числа не показательны.

## Что это значит для бюджета

| Проверка | Как принимать |
|---|---|
| FPS ≥ 50 | только на живом устройстве (браузер пользователя) |
| Сравнение версий | один и тот же режим, реальное время, 3 замера |
| Headless | годится для «не хуже/не лучше», не для абсолютных цифр |

## Красная линия

Замер с `--virtual-time-budget` **не считается измерением** и не может служить
основанием для отката или оптимизации.
