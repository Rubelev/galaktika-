## TZ-261122-01 · Публичные страницы тел Солнечной системы (50 URL)

**Цель:** дать поисковику 50 уникальных страниц с реальными числами о телах системы, чтобы по запросам «3D солнечная система», «колония на Марсе», «Луна в игре» сайт вообще мог показываться, а игрок попадал из поиска сразу на страницу тела с кнопкой «Играть».

**Механика:**

1. Новый генератор `tools/build_seo_pages.py` читает **тот же** `js/catalog.js`, который уезжает на сайт (не второй источник): `bodies` (48 записей: 42 в `sol`, 6 в `war`) и `systems` (2 записи).
2. Для каждого тела пишется файл `deploy-host/site/p/planet/<id>.html`; для каждой системы — `p/system/<id>.html`. Имена файлов — строго из `id` каталога (`mars`, `earth`, `ceres`, `warprime`…), не транслит и не руками.
3. Шаблон страницы: один `<h1>` (имя тела), таблица «параметр → значение» из каталога (`a`, `e`, `i`, `P`, `radius_km`, `role`, `parent`, `type`), текст 500–800 знаков, 3 вопроса FAQ, 1 картинка, 3+ внутренние ссылки, кнопка «Играть» → `/`.
4. Абзац текста собирается из **9 шаблонов по `role`** + 1 общий для пустого значения: в каталоге 10 значений `role` (`scrapyard` 14 тел, `factory` 12, `workshop` 11, `betting` 4, `front` 2, `home` 1, `arena` 1, `arena-portal` 1, `star` 1, пусто у `warsun` — 1), с подстановкой чисел. Луны получают дополнительный абзац про `parent`.
5. Картинки: батч-съёмка через `?pv=<id>&shot=1` (`js/planetview.js:805-810` уже скрывает оверлеи) в `images/planets/<id>.png`; из неё же генерится `og:image` 1200×630.
6. `.htaccess` получает 4 правила: `^planet/([a-z0-9_-]+)/?$` → `p/planet/$1.html`, то же для `system`, 301 с варианта без слэша, 404 для неизвестного `id`.
7. `deploy.ps1` вызывает генератор **до** упаковки (шаг «1. сборка», `deploy.ps1:88-124`). Генератор пишет и `sitemap.xml` целиком, включая 50 новых URL и `lastmod`.

## TZ-261122-02 · Публичная таблица лидеров и профиль капитана

**Цель:** сделать так, чтобы у сайта была живая страница с рейтингом (свежий контент, брендовые запросы «галактика рейтинг») и страницы капитанов с нормальной OG-карточкой, по которым игроки сами приносят ссылки в соцсети — но без публикации чужих данных без согласия.

**Механика:**

1. `/leaders/` — серверная страница (PHP), отдаёт HTML с тремя таблицами по 20 строк: население, кредиты, корабли. Данные берёт **внутренним вызовом** существующего публичного `api.php?action=leaderboard` (`api.php:2990-3012`), без создания второго источника.
2. Ниже — блок арен: 6 событий из `lib/world_econ_data.php:7-14` (вместимость, билет) и расписание заездов Тарсиса из `lib/race_core.php:18-24` («старт через N», каждые 6 ч от эпохи 2026-01-01).
3. Кэш страницы — **60 с** (файл `data/cache/leaders.html` + `mtime`), чтобы рейтинг был живым, а API не дёргался на каждый заход краулера.
4. `/captain/<code>/` — страница капитана по **8-символьному коду** (`[a-z0-9]`), а не по e-mail и не по нику: код уже генерируется как `substr(md5(...),0,8)` (`api.php:2396`).
5. Публичность — **по флагу игрока** `publicProfile = true` в профиле. Нет флага → **404**, не «страница с пустым профилем».
6. Источники для страницы капитана — только серверные: `users.json` (имя, фракция, стадия колонии), `trophies.json` (`api.php:83`), `ranks.json` (`api.php:75`), достижения (`api.php:522,539`). **Профиль, который приходит от клиента** (`api.php:1291-1316`), для публичной страницы **не используется**.
7. OG-картинка капитана генерится по образцу `deploy-host/site/ship-render.html:1-48`: имя, фракция, стадия на градиенте 1200×630; при сбое — статичный `images/og-galaktika.png`.
8. Реф-ссылка переезжает на `/r/<code>`: **302** на `/?ref=<code>` + `X-Robots-Tag: noindex`; на `/r/<code>` — статическая страница приглашения с OG «Капитан X приглашает в Галактику» и кнопкой «Принять».
9. Точные кредиты на странице **не выводятся**: только место в рейтинге по кредитам. (API продолжает отдавать их как раньше — см. оговорку.)

**Числа:**

| Параметр | Значение | Обоснование |
|---|---:|---|
| Строк в каждой таблице | **20** | столько отдаёт API (`array_slice($rows, 0, 20)`, `api.php:3012`) |
| Таблиц | **3** | `by=population / credits / ships` — все три ветки уже есть (`api.php:3008-3010`) |
| TTL кэша `/leaders/` | **60 с** | баланс «живость ↔ нагрузка»; игрок видит разницу не больше одного тика |
| Длина кода капитана | **8** символов `[a-z0-9]` | как `refCode` (`api.php:2396`); 36^8 ≈ 2,8·10^12 вариантов — перебор бессмысленен |

| p95 ответа | **≤ 300 мс** | статика + чтение json-файлов; замер на 50 rps |
| Email в публичном HTML | **0** | проверка регуляркой `@` по всему HTML |
| Кредиты точные | **не выводятся** | снижаем риск, что публичная страница усиливает уже существующую утечку (`api.php:3003`) |
| Обновление OG капитана | при смене стадии/трофеев | иначе карточка «залипает» на старом звании |

**Границы:**

- **Не меняем** контракт `leaderboard`: поля и сортировки остаются (`api.php:2990-3012`) — его уже использует клиент (`js/social.js:120-127`).
- **Не публикуем** e-mail, точные кредиты, координаты колоний, историю входов.
- **Не включаем** публичность по умолчанию: `publicProfile` — только добровольно, `false`/пусто → 404.
- **Не трогаем** начисление рефералов: 25 000 кр + 10 кристаллов обоим (`api.php:2406-2407`, `2422-2424`) — механика не меняется, меняется только форма ссылки.

- **Не добавляем** рейтинги арен/дуэлей: сезонов и серверного счёта побед нет — это отдельное ТЗ (см. `agents/TZ-REVIEW.md` о `leaderboard`).

1. `GET /leaders/` без токена и без cookies → **200**, в HTML **60** строк данных (3 × 20), значения совпадают с `api.php?action=leaderboard` (diff = 0 на одном снимке).
