# КОМАНДА «ГАЛАКТИКИ»: роли, поток, приёмка

Логика взята из общего репозитория (`state\ОРГСТРУКТУРА.md`) и адаптирована под продукт:
меньше ролей, но та же цепочка и те же требования к доказательствам.

---

## 1. Роли

| Роль | Кто | Что делает | Граница |
|---|---|---|---|
| **Руководитель** | я (агент-лидер) | ставит задачи, режет на срезы, держит очередь, принимает результат числом, возвращает на доработку | сам не пишет код в обход агентов |
| **Агент ядра** | [AGENT-CORE.md](AGENT-CORE.md) | время, движение, масштаб, координаты, каталог | не трогает UI и экономику |
| **Агент планетарного вида** | [AGENT-PLANET-VIEW.md](AGENT-PLANET-VIEW.md) | экран `?pv=`, зоны, тур, рубильники | не трогает ядро |
| **Агент игровых систем** | [AGENT-GAME-SYSTEMS.md](AGENT-GAME-SYSTEMS.md) | еда/заводы, зрелища, казино, рынок, колония | не трогает ядро и вид |
| **Тестировщик** | [AGENT-QA.md](AGENT-QA.md) | проверяет каждую доработку: регресс + новое + границы + данные + скриншот | ничего не правит, не деплоит |
| **Маркетолог** | [MARKETING.md](../docs/MARKETING.md) | рыночный успех: воронка, каналы, контент, метрики | не меняет баланс и данные игроков |

## 2. Поток задачи

```
1. ПОСТАНОВКА  Руководитель: задача + критерий «что считается сделанным» (число).
      ↓
2. РАЗБОР      Руководитель (при сложности — с агентами): какой агент, какие файлы,
               чем проверяем, что НЕ трогаем. Срез ≤ 2 часов работы.
      ↓
3. ИСПОЛНЕНИЕ  Один агент = одна зона = один срез. Не пересекаются по файлам.
      ↓
4. ТЕСТИРОВАНИЕ Тестировщик: регресс + новый критерий + границы + старые аккаунты.
               Отчёт PASS/FAIL с числами.
               FAIL → тестировщик создаёт карточку дефекта `DEF-YYMMDD-NN`
                      в agents/DEFECTS.md (ожидалось/получено/доказательство).
      ↓
5. ПРИЁМКА     Руководитель: «принято» только с числом; иначе возврат с причиной.
               Дефект: руководитель переводит карточку в «принят руководителем».
               ДО ЭТОГО разработчик задачу не берёт — «пока не принято, не выполняем».
               Деплой делает руководитель, после тестировщика.
```

---

## 3. Правила нарезки (работа руководителя)

```
1. Один срез — один объект или один экран.
2. Срез ≤ 2 часов; больше — режется по объектам.
3. В срезе: что делать, чем проверить, что НЕ трогать.
4. Зависимые срезы — последовательно, независимые — параллельно (макс 2 исполнителя).
5. Перед выдачей проверить, не занят ли объект другим агентом.
```

## 4. Приёмка: минимум доказательств

| Тип работы | Доказательство |
|---|---|
| Логика/экономика | тест + число «до/после» |
| Данные | запрос: было → стало |
| Интерфейс | скриншот целого окна (ПК + телефон при вёрстке) |
| Сервер | `brief.py audit` 47/47 + `status` |
| Деплой | версия `v=NNNN` + проверка на живом URL |

**Не принимается:** «проверил, всё хорошо», «синтаксис ок», «exit 0» без результата.

## 6. Эскалация

```
Задача стоит > 30 мин без причины      → переназначить или уточнить критерий
Дважды возвращена по одной причине     → пересмотреть постановку, а не исполнителя
Требуется решение по деньгам/данным    → вопрос пользователю с вариантами
Ограничение платформы                  → зафиксировать в docs и сменить подход
```

---

## 7. Бюджет внимания (правило экономии)

```
1. Ответ руководителя — до 10 строк: числа + решения.
2. Отчёт агента — до 10 строк, полный текст в файл.
3. Не пересказывать отчёт из файла.
4. Не запускать больше двух агентов одновременно.
```

## 8. Где править файлы (после инцидента v=1271)

```
1. JS правится ТОЛЬКО в src/galaktika.Web/wwwroot/js/ — deploy.ps1 копирует src → site,
   правка сразу в deploy-host/site/js будет стёрта деплоем (так чуть не откатили фикс H-01).
2. PHP правится в deploy-host/site/ (это и есть источник для сервера).
3. Перед деплоем: md5 пары src↔site для изменённых js должны совпадать.
4. Версия ?v= для js поднимается в App.razor (см. п.5 для solar) — make-static берёт список оттуда.
```

5. Версия `solar.js?v=` в проде = `-Version` деплоя (её ставит make-static), а не число из App.razor.
   App.razor — для локального Blazor-режима; расхождение цифр там дефектом не считается.
   Внутренние import() обязаны иметь свою версию: `encyclopedia.js?v=2` (проверено CDP:
   без версии браузер берёт fromMemoryCache, с версией — transferSize>0).
